COS202 PROGRAMMING II – LAB ASSESSMENT PROJECT
Case Study: Smart Clinic Appointment & Patient Management System
(SCAPMS)
PROJECT OVERVIEW
A university clinic wants to develop a Smart Clinic Appointment & Patient
Management System (SCAPMS) to manage patients, medical services,
appointments, queues, consultations, and basic clinic reports.
The system should provide an interactive graphical user interface through which
clinic staff can register patients, schedule and manage appointments, search and
sort patient records, manage waiting queues, and generate simple reports. You are
required to build a fully functional C++ application with the following requirements.
CORE REQUIREMENTS
1. Advanced Object-Oriented Programming
Design a class hierarchy containing:
a. Abstract Class
Create an abstract class called PatientRecord which should contain common
information such as:
i. Patient ID
ii. Name
iii. Age
iv. Contact information
This class must contain at least one pure virtual function.
b. Subclasses
Create at least three subclasses:
i. GeneralPatient
ii. EmergencyPatient
iii. FollowUpPatient
Each subclass should provide behaviour appropriate to its patient type.
c. Interface / Abstract Interface
Create an interface-like abstract class called Appointable which should define
operations that can be implemented by patient types that can be scheduled for
appointments. For example:
i. scheduleAppointment()
ii. cancelAppointment()
d. Polymorphism
Implement a function that can process different PatientRecord objects through a
common base-class pointer or reference. (The program should demonstrate runtime
polymorphism.)
e. Encapsulation and Composition
-Create a class called ClinicDatabase which contains a collection of patient records.
-Also create an Appointment class containing relevant appointment information. A
patient should be associated with one or more appointments.
f. Class Organisation

3. Using Data Structures
The system must use appropriate C++ data structures as follows:
a. Vector
Use std::vector to store registered patients.
b. Queue
Use std::queue to manage patients waiting for consultation. (The patient who joins
the queue first should normally be served first.)
c. Stack
Use std::stack to implement an Undo Last Administrative Operation feature.
For example, an administrator may:
i. Delete a patient
ii. Remove an appointment
iii. Modify a patient record
The system should allow the most recent administrative operation to be reversed.
d. Array
Use a fixed-size C++ array to implement a small cache for "Frequently Accessed
Patient Records".
For example:
PatientRecord* recentPatients[10];
[The implementation may use a different appropriate design.]
4. Searching Algorithms
You must implement at least two searching algorithms manually.
a. Linear Search to search for a patient by Patient ID.
b. Binary Search: Implement binary search for a suitable field after the patient
records have been sorted.
c. Recursive Search
You may also implement a recursive search for Patient name.
The program should use an appropriate searching technique depending on the state
of the data. [eg. Sorted or unsorted].
5. Sorting Algorithms
Implement two sorting algorithms manually.
You may choose from:
i. Selection Sort
ii. Insertion Sort
iii. Merge Sort
iv. Quick Sort
The system should allow patient records to be sorted by at least two of the following:
i. Patient name
ii. Patient ID
iii. Age
iv. Appointment date
Algorithm Selection
The GUI should provide a dropdown/combo box allowing the user to select the
sorting algorithm.
For example:

[ Selection Sort ▼ ]
Sort By:
[ Patient Name ▼ ]
[ SORT ]
You must explain why the selected sorting algorithm is appropriate for the particular
situation.
